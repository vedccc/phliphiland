Why
“Turning test mode on basically means that it only replies to my reservation and his reservation. If we turn test mode off, it replies to everyone.”
How
  • Today this list lives in a server setting (ALLOWED_CONVERSATION_IDS) that only a developer can change from the command line. It moves into the database, and the webhook reads it on every message, so the switch takes effect on the next guest message with no redeploy.

  • Only admins can turn it on or off. Other users see the current state but no switch.
  • The test reservations are always these two. They're shown under the switch but can't be edited from the dashboard.

3 · Never answer inquiries

Agent
What
Before the AI does anything, it checks the Guesty status of the reservation the message belongs to:
Guesty statusWhat the AI does
Confirmed, checked in, checked outReplies as it does today
Inquiry, declined, expiredNothing. Logged as “inquiry not answered”. Your team answers in Guesty.
Request to book (awaiting approval), cancelledSee questions below
Why
“It's important that inquiries aren't getting answered … sometimes with the way Guesty works, we might accidentally be answering an inquiry.”
Checked
  • No inquiry is being answered right now, but only because test mode blocks everyone except the two test conversations.
  • There is no inquiry filter in the code today. The AI already fetches the reservation from Guesty, status included, but never looks at the status. Once test mode is turned off, an inquiry would get a reply.
  • So this must ship with or before test mode goes off.
  • Decided: it applies with test mode on as well as off. Even a test conversation gets no reply if the message belongs to an inquiry.
  • Built (not deployed). Both test bookings show as “confirmed” in Guesty, so they still get replies.
How
  • An allow-list, not a block-list: only the statuses in the first row get replies. If Guesty ever adds a new status, it gets silence, not an answer.
  • It catches the tricky case you mentioned: a past guest sending a new inquiry. Guesty files that message under the new inquiry, not the old stay, so it's skipped.
  • No extra Guesty call and no extra cost. The AI already fetches the status today, and the check runs before any AI step.
Question 1: Should a request to book (guest has asked to book, you haven't approved yet) get AI replies? I recommend no. It's still a sales conversation, like an inquiry.
Question 2: Should a guest whose booking was cancelled get AI replies? I recommend no. Questions about refunds and rebooking are yours to handle.

6 · Jerall · inquiries AI (Gerald)

On hold: Gerald's written feedback is being forwarded separately. These two changes come from the call. The final prompt wording waits for his notes, so both changes are made in one pass.
Prompt
What
  • The first reply answers what the person actually asked. If they only said hello, it asks how it can help.
  • It asks for dates and gets a quote only once they're asking about availability or price.
  • It still negotiates exactly as it does now, but only after they ask.
Why
“It shouldn't start with that, because otherwise people will immediately assume a discount … we can just open with ‘Hey, how can I help?’ or answer the questions.”
Checked
  • Discounts are already locked: the AI can't see the discount range until the guest asks for a better price. That has been in place since 4 Aug.
  • What still feels like a sales opener is step 1 of the prompt. It tells the AI to ask for nights and dates straight away, then quote a price. That's the part to change.
Agent
What
  • The inquiries AI can answer questions about the property they're asking about, from its knowledge base.
  • It can also search all properties' knowledge bases: “Do you have another property with a hot tub?” → “Yes, Property C has one.”
Why
“Not only from the knowledge base of the property they're inquiring about, but from all knowledge bases.”
How
  • Today the inquiries AI has no knowledge base at all. Its prompt says “you do not have the house manual”. Only the booked-guest AI reads it.
  • Add a search tool over all properties' knowledge bases. It returns guest-facing facts only, never door codes, wifi passwords or check-in instructions, because the person hasn't booked.
  • If the answer isn't in any knowledge base, the AI says it will check with the team. It never guesses.
Question 3: When it suggests another property (“Property C has a hot tub”), should it first check that property is free on their dates? I recommend yes when it already knows their dates. Otherwise it names the property and asks for dates.
